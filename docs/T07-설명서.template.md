## ② 왜 그걸 골랐나

- **직접 구현 + 내장 scrypt를 고른 이유**: 6번이 "외부 패키지 없이 Node.js + SQLite"로 만들어져 있어 의존성을 하나도 늘리지 않고 이어 붙이는 쪽이 설명하기 쉽고, 비밀키를 가진 서명 토큰이 없어서 지킬 비밀키 자체가 없습니다. 비밀번호 해시만큼은 직접 만들면 위험하므로 검증된 표준 함수(scrypt)에 맡겼습니다.
- **scrypt를 고른 이유**: bcrypt·argon2는 네이티브 패키지를 새로 설치해야 하는데 배포 이미지(`node:24-slim`)에서 빌드가 깨질 위험이 있고, scrypt는 메모리를 많이 써서 GPU 대입 공격에 강하면서 Node에 이미 들어 있습니다(PBKDF2보다 메모리 경도가 있음).
- **함께 검토했지만 고르지 않은 방법**
  - *Firebase Auth·Auth0 같은 인증 서비스*: 가입자 정보가 외부로 나가고 심사하는 사람이 서비스 설정에 접근해야 해서 "로그인 없이 첫 화면까지 열려야 한다"는 요구와 배포를 복잡하게 만든다고 판단해 고르지 않음.
  - *Passport·bcrypt 같은 npm 라이브러리*: 쓸 만하지만 6번의 "외부 패키지 없음" 구조를 깨고 네이티브 빌드 위험이 있어 고르지 않음.
  - *JWT(서명된 토큰)*: 로그아웃·비밀번호 변경 때 이미 나간 토큰을 서버가 끊기 어렵고 비밀키를 지켜야 해서, 서버가 세션을 직접 지우는 방식을 골랐음.
- **404를 고른 이유**: 403은 "그 번호의 자료가 있다"는 사실을 알려 주므로, 없는 자료와 남의 자료를 같은 404·같은 문구로 답했습니다.

## ③ 어디를 어떻게 고쳤나

네 흐름이 소스의 어디를 지나는지 (줄 번호는 이 문서를 만든 시점의 커밋 기준):

| 흐름 | 지나는 곳 |
| --- | --- |
| **가입** | 화면 `public/auth-ui.js` `showAuth()` → `POST /api/auth/signup` → `server.js` 라우트(`route('POST','/api/auth/signup')`) → `auth.js` `signup()`: 이메일 소문자 정리·10자 이상 비밀번호 확인 → `hashPassword()`(scrypt+새 소금값) → `users`에 저장(이메일 `UNIQUE COLLATE NOCASE`가 중복 가입을 막음) → `startSession()` |
| **로그인** | `POST /api/auth/login` → `auth.js` `login()`: 이메일로 사용자 조회, **없어도 가짜 해시로 같은 계산**을 한 뒤 `verifyPassword()`(`timingSafeEqual`) → 실패는 이메일 없음·비밀번호 틀림 모두 같은 401·같은 문구 → 성공하면 `startSession()`이 토큰을 만들어 SHA-256만 `sessions`에 저장하고 `Set-Cookie`(HttpOnly·SameSite=Strict·7일, HTTPS면 Secure) |
| **로그아웃** | `POST /api/auth/logout` → `auth.js` `logout()`이 `sessions`에서 그 줄을 **서버에서 삭제**하고 쿠키를 지움. 비밀번호 변경(`changePassword()`)은 그 사람의 세션을 전부 지움 |
| **자료 조회** | 모든 `/api/*` 요청은 `server.js` 핸들러에서 ① 다른 사이트의 쓰기 요청 거절(`sameHost`, 505줄 근처) → ② `auth.userFromRequest()`로 쿠키→세션→사용자 확인(만료되면 삭제) → 공개 길(`health`·`signup`·`login`)이 아니면 **세션이 없을 때 401**(508줄 근처) → ③ 각 함수에 `c.user.id`(요청이 아니라 세션에서 나온 값)를 넘김 |

**주인 확인이 일어나는 위치** (남의 자료가 거절되는 곳):

| 위치 | 하는 일 |
| --- | --- |
| `server.js` `planRow()` (109줄) `WHERE p.id=? AND p.user_id=?` | 계획 한 건 조회·고치기·할 일 만들기·돌아보기 넘기기가 모두 여기를 먼저 지나며, 남의 계획은 없는 계획과 똑같이 404 |
| `server.js` `taskRow()` (216줄) `JOIN plans … AND p.user_id=?` | 할 일 한 건 조회·고치기·지우기·완료·되돌리기·실행 기록 만들기가 모두 여기를 먼저 지남. **거절을 먼저 하고 저장은 그 뒤**(변경 SQL은 `taskRow()` 다음 줄) |
| `server.js` `taskFilter()` (171줄) `t.plan_id IN (SELECT id FROM plans WHERE user_id=?)` | 할 일 **목록**과 돌아보기 집계가 이 조건을 지남(한 건 조회와 다른 코드 경로라서 따로 걸었음) |
| `server.js` `listRuns()` (329줄) `p.user_id=?`, `listSnapshots()`, `exportAll()` (397줄) | 실행 기록 목록·저장한 돌아보기·내보내기도 같은 주인 조건 |
| `server.js` `keyOf()` | 중복 방지용 요청 키도 `사용자번호:키`로 계정별로 분리(남의 키와 부딪히지 않음) |
| `db.js` `migrate()` | 6번 DB의 `plans`·`review_snapshots`에 `user_id` 열을 더함 |
| `claim-legacy.js` | 주인 없는 6번 자료를 내 계정으로 옮기는 한 번용 스크립트(아래) |

**6번 자료를 내 계정으로 옮기기**: 배포 서버에서 먼저 화면으로 가입한 뒤 `fly ssh console -C "node claim-legacy.js 내이메일"`을 한 번 실행합니다. 주인 없는(6번에서 만든) 계획·저장한 돌아보기가 그 계정으로 옮겨지고, 할 일·실행 기록·완료·태그·수정 이력은 계획에 딸려 따라갑니다(6번 DB 복사본으로 검증: 계획 1건·할 일 6건·실행 기록 4건·완료 3건이 계정 #1 소유가 되고, 두 번째 실행은 0건을 옮김). 자동으로 옮기지 않은 이유: 먼저 가입한 아무나 6번 자료를 가져가지 못하게 하려는 것.

## ⑥ 아직 못 막은 것 (위험한 이유와 함께)

| 못 막은 것 | 왜 위험한가 |
| --- | --- |
| **무차별 대입(로그인 시도 횟수 제한 없음)** | 누군가 한 계정에 비밀번호를 계속 바꿔 가며 시도해도 막지 못합니다(scrypt가 시도당 ~0.1초 느리게 할 뿐). 약한 비밀번호(10자 이상이어야 한다는 규칙뿐, 흔한 비밀번호 목록 대조 없음)는 뚫릴 수 있습니다. |
| **로그인 한 번이 비싼 계산(서버 부담)** | 로그인·가입마다 scrypt 32MB·~0.1초를 쓰므로, 많은 요청을 한꺼번에 보내면 작은 서버(256MB)가 느려지거나 멈출 수 있습니다(서비스 거부). |
| **이메일 확인·비밀번호 재설정 없음** | 비밀번호를 잊으면 되찾을 방법이 없고, 남의 이메일 주소로 먼저 가입해 선점할 수 있습니다. |
| **가입 때 「이미 가입된 이메일입니다」로 알려 줌** | 어떤 이메일이 가입자인지 알아낼 수 있습니다(로그인 실패 문구는 같게 했지만 가입 쪽은 열려 있음). |
| **두 번째 인증 수단 없음** | 비밀번호가 새면 곧바로 계정 전체가 열립니다. |
| **보안 사건 기록(로그) 없음** | 로그인 실패·남의 자료 시도를 서버가 남기지 않아 공격이 있어도 알 수 없습니다(비밀번호 원문을 로그에 남기지 않으려고 요청 로그 자체를 두지 않음). |
| **세션을 훔쳐 가면 7일간 유효** | 공용 PC에서 로그아웃을 잊거나 쿠키가 탈취되면 만료 전까지 막을 방법이 없습니다(화면에서 내 세션 목록을 보고 끊는 기능 없음). 비밀번호를 바꾸면 모두 끊기는 것이 유일한 방법입니다. |
| **HTTPS 강제는 배포 설정(`force_https`)에만 의존** | 서버 코드가 `Strict-Transport-Security` 헤더를 보내지 않아, 처음 접속을 http로 하는 사람은 한 번 가로채일 수 있습니다. |
| **계정 삭제 뒤에도 SQLite 파일 조각에 옛 내용이 남을 수 있음** | 행은 지워지지만 파일 안의 빈 공간·로그(WAL)에 흔적이 남을 수 있어 "완전 삭제"라고 말할 수 없습니다. |
