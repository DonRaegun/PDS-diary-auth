# 플랜두씨 다이어리 2 (과제 7: 가입·로그인 + 5일 관찰)

계획(Plan) → 실제로 한 일(Do) → 돌아보기(See)가 이어지는 다이어리. 가입·로그인한 사람만 자기 자료를 봅니다(서버 세션 + scrypt, 외부 패키지 없음). 자료는 서버의 SQLite DB(`data/diary.sqlite`)에 저장됩니다. 인증 설명서: [docs/T07-설명서.md](docs/T07-설명서.md).
외부 패키지 없이 Node.js(22.5+, `node:sqlite`)만 씁니다. 비밀키·환경 비밀값은 사용하지 않습니다.

```bash
npm start          # http://localhost:3000
npm run seed       # PDS_SEED_EMAIL·PDS_SEED_PASSWORD(환경 변수)로 만든 계정에 시작 자료를 넣음
node claim-legacy.js 내이메일   # 6번에서 만든 주인 없는 자료를 내 계정으로 옮김(한 번)
node scripts/build-doc.js        # 확인 기록을 실제 요청으로 만들어 docs/T07-설명서.md 생성
npm test           # API·DB 제약·스키마 계약 테스트
```

환경 변수: `PORT`(기본 3000), `PDS_DB`(DB 파일 경로). 배포할 때는 DB 파일이 사라지지 않는 디스크(영구 볼륨)를 `PDS_DB`로 지정해야 새로고침·재시작 뒤에도 자료가 남습니다.

## 짧은 확인 방법

**① 어디로 가나요**
배포 주소(제출 시 기입) 또는 로컬 `http://localhost:3000`을 새 시크릿 창에서 엽니다. 첫 화면은 로그인 화면이며, 이 화면까지는 계정 없이 열립니다. 심사용 계정은 만들어 두지 않았으니 「가입하기」로 새로 만드세요(시험용 이메일·비밀번호 10자 이상).

**② 세 단계 안에 무엇을 하나요**
1. 「가입하기」로 계정을 만들고, 「계획」에서 계획 한 건을 만듭니다. 주소창에 `#/tasks`를 넣어도 로그인 전에는 로그인 화면만 나옵니다.
2. 「내 계정」 → 「로그아웃」 뒤 같은 주소(`/api/plans`)를 열어 봅니다. 다른 이메일로 가입한 두 번째 계정으로는 첫 계정의 할 일 번호(`/api/tasks/1`)가 열리지 않는지 봅니다.
3. 로그인 상태에서 위쪽 「내보내기(JSON)」로 내 자료 파일 한 개를 받습니다.

**③ 무엇이 보이면 통과인가요**
- 로그아웃 뒤 `/api/plans`는 `401 {"error":"로그인이 필요합니다"}`.
- 남의 할 일 번호는 읽기·수정·삭제 모두 `404 {"error":"할 일을 찾을 수 없습니다"}`이고, 목록에는 내 자료만 나옵니다.
- 같은 이메일로 다시 가입하면 409, 없는 이메일과 틀린 비밀번호는 같은 문구(`이메일 또는 비밀번호가 올바르지 않습니다`).
- 내보낸 JSON에는 내 자료만 있고 비밀번호(해시 포함)는 없습니다.

**④ 안 될 때는 무엇이 보이나요**
- 입력이 잘못되면 화면 오른쪽 아래에 빨간 안내가 뜨고 저장되지 않습니다. 서버에 닿지 못하면 「화면을 불러오지 못했습니다: …」와 **다시 시도**.
- 세션이 만료되면(7일) 로그인 화면으로 돌아갑니다. 비밀번호를 잊으면 되찾을 방법이 없습니다(설명서 ⑥).

## 구성

| 파일 | 역할 |
| --- | --- |
| `db.js` | SQLite 스키마(표·제약·유일 인덱스)와 6번 DB 이전 |
| `auth.js` | 가입·로그인·로그아웃·비밀번호 변경·계정 삭제, 세션, scrypt |
| `experiment.js` | 5일 관찰(질문·지표·날짜별 기록·규칙 한 번 변경·앞뒤 비교) |
| `server.js` | HTTP API + 세션 확인 + 주인 확인 + 정적 파일 + 보안 헤더(CSP 등) |
| `public/` | 화면(순수 JS, `innerHTML` 미사용) |
| `contracts/pds-schema-v3.json` | 최종 표·항목·관계·날짜 규칙 (테스트가 실제 DB와 대조) |
| `seed.js` | 내 시작 자료 |
| `test/` | `node --test` 테스트 |

## 핵심 규칙
- **수정 이력**: `plans`는 현재 값, `plan_revisions`는 처음 값과 모든 수정본(덮어쓰지 않음). 계획 ID는 그대로.
- **중복 완료 방지**: ① `Idempotency-Key` 재사용, ② 이미 완료면 무시, ③ DB 부분 유일 인덱스 `uq_completions_active`. 버튼 잠금에 의존하지 않습니다.
- **실행 기록**은 `runs` 표에 따로 저장되고 `tasks` 값을 건드리지 않습니다.
- **시간**: 달력 날짜는 서울 `YYYY-MM-DD`, 시각은 UTC로 저장해 서울 시각으로 표시, 시간 양은 분.
- **정렬**: 화면에 기준을 적고, 같은 값이면 마감일 → 우선순위 → 등록 번호 순. 거르기·정렬은 서버(SQL)에서 합니다.
- **돌아보기**: 계획 수 = 지우지 않은 할 일 수, 지연 = 미완료이면서 마감일 < 오늘(서울), 막힘 = 막힌 이유가 적힌 실행 기록이 있는 할 일 수. 숫자를 누르면 같은 조건의 목록으로 갑니다.
